# Fida-Ride mobile architecture

The Flutter clients use Dart Pub workspaces for one shared dependency resolution across all apps and packages.

```text
Fida-Ride/
├── apps/
│   ├── fida_rider/
│   │   ├── pubspec.yaml
│   │   └── lib/
│   │       ├── main.dart
│   │       └── app/rider_app.dart
│   └── fida_driver/
│       ├── pubspec.yaml
│       └── lib/
│           ├── main.dart
│           ├── app/driver_app.dart
│           └── infrastructure/driver_telemetry_publisher.dart
├── packages/
│   ├── fida_api/       # Dio REST + Go telemetry WebSocket
│   ├── fida_location/  # Geolocator + LocationBloc + publisher port
│   └── fida_ui/        # Shared Google Map screen and marker models
└── pubspec.yaml        # Pub workspace root
```

## Dependency direction

```text
apps/fida_rider  ─┐
                  ├──> fida_ui ───> fida_location
apps/fida_driver ─┤
                  ├──> fida_location
                  └──> fida_api
```

The shared location package knows only the `LocationPublisher` interface. It does not import the API package. The driver app owns the adapter that bridges `LocationPublisher` to `TelemetryWebSocketClient`, preserving clean dependency direction.

## Bootstrap

Flutter 3.47 / Dart 3.13 or newer stable is required.

From the repository root:

```bash
flutter pub get
```

The platform runner directories are intentionally generated by the Flutter SDK rather than hand-maintained boilerplate. On a machine with Flutter installed, create them once before the first device build:

```bash
cd apps/fida_rider
flutter create --platforms=android,ios --project-name=fida_rider .

cd ../fida_driver
flutter create --platforms=android,ios --project-name=fida_driver .
```

Re-run `flutter pub get` at the repository root after platform generation.

## Local driver launch

For Android emulator access to services bound on the development host, the default telemetry endpoint is `ws://10.0.2.2:8080/ws/driver`.

```bash
cd apps/fida_driver
flutter run \
  --dart-define=FIDA_TELEMETRY_WS_URL=ws://10.0.2.2:8080/ws/driver \
  --dart-define=FIDA_ACCESS_TOKEN='<driver-jwt>' \
  --dart-define=FIDA_DRIVER_ID='<driver-uuid>'
```

`FIDA_ACCESS_TOKEN` and `FIDA_DRIVER_ID` are development bootstrap inputs only. Production builds should inject the authenticated runtime session from the login/session repository rather than compile credentials into the application.

## Mobile platform configuration

Google Maps API keys and location permissions remain platform-owned configuration:

- Android: configure Maps API metadata and fine/coarse location permissions in `AndroidManifest.xml`.
- iOS: configure the Maps SDK key and `NSLocationWhenInUseUsageDescription` in the Runner configuration.

The driver tracking stream uses `LocationAccuracy.bestForNavigation` with a 5 meter distance filter. The telemetry WebSocket uses the JWT in the `Authorization` upgrade header, keeps only the latest unsent GPS packet while offline, and reconnects automatically.
